# lambda/

Two Python 3.12 Lambda functions forming the cloud data pipeline: one ingests binary MQTT payloads from IoT devices and writes to DynamoDB; the other serves HTTP queries from the frontend.

---

## Functions

### ingest.py

**Trigger:** AWS IoT Core topic rule, invoked per MQTT message on `weather-stations/+/data`.

**Responsibility:** Decode the 11-byte binary `WeatherPacket`, independently validate its CRC-16/CCITT checksum, and write the decoded fields to DynamoDB.

**Response codes:**

| Code | Condition |
|---|---|
| 200 | Successfully decoded and stored |
| 400 | No `payload` or `awsIotData` field in the event |
| 422 | Wrong packet length or CRC mismatch |

### query.py

**Trigger:** API Gateway HTTP API — `GET /readings`.

**Responsibility:** Query DynamoDB for a device's readings within a time range and return them as JSON.

**Query parameters:**

| Parameter | Required | Default | Notes |
|---|---|---|---|
| `device_id` | Yes | — | Integer station identifier |
| `start` | No | `end − 86400` | Unix epoch, inclusive |
| `end` | No | now | Unix epoch, inclusive |
| `limit` | No | 100 | Maximum readings to return |

`start`, `end`, and `limit` must be integers; non-integer values return 400. `start > end` returns 400. Results are sorted ascending by timestamp; `limit` retains the newest N readings within the range.

**Response shape:**

```json
{
  "device_id": 42,
  "readings": [
    {
      "device_id":     42,
      "timestamp":     1700000000,
      "temperature_c": 23,
      "humidity_pct":  65
    }
  ]
}
```

## DynamoDB Schema

Both functions share the same table (name passed via `DYNAMODB_TABLE` environment variable).

| Attribute | DynamoDB type | Description |
|---|---|---|
| `device_id` | N (hash key) | Station identifier |
| `timestamp` | N (range key) | Unix epoch, UTC |
| `temperature` | N | Whole degrees C |
| `humidity` | N | Whole % RH |
| `version` | N | Protocol version from packet |
| `ttl` | N | Epoch; DynamoDB TTL — records expire after 7 days |

The ingest Lambda is granted only `dynamodb:PutItem`. The query Lambda is granted only `dynamodb:Query`. Neither has broader table access.

## Directory Layout

```
src/
  ingest.py          IoT payload decoder and DynamoDB writer
  query.py           HTTP query handler

tests/
  test_ingest.py     Unit tests: CRC helpers, decode, handler responses
  test_query.py      Unit tests: parameter validation, response shape, round-trip
  test_integration_live.py   Live tests against the deployed stack
  seed_data.py       Helper: write test fixtures directly to DynamoDB
  clear_seed_data.py Helper: remove seeded fixtures

pytest.ini           Registers the `live` marker
dist/                Lambda deployment ZIPs (generated by terraform apply)
```

## Dependencies

The Lambda functions use only the Python standard library and `boto3` (pre-installed in the Lambda runtime). No `requirements.txt` is needed for deployment.

For running tests locally:

```
boto3
moto[dynamodb]
pytest
pytest-cov
```

## Developer Guide

### Install test dependencies

```bash
cd lambda
pip install boto3 "moto[dynamodb]" pytest pytest-cov
```

### Run unit tests

```bash
pytest tests/test_ingest.py tests/test_query.py -v
```

These tests use `moto` to mock DynamoDB in-process — no AWS credentials or network access required.

```
tests/test_ingest.py::TestCrc::test_known_value PASSED
tests/test_ingest.py::TestDecodePacket::test_round_trip PASSED
...
37 passed in 0.4s
```

### Run with coverage

```bash
pytest tests/test_ingest.py tests/test_query.py --cov=src --cov-report=term-missing
```

### Run mutation tests

```bash
pip install mutmut
mutmut run
mutmut results
```

Mutmut mutates `src/` and runs the unit test suite against each mutant. Configuration is in `setup.cfg`. An HTML report can be generated with `mutmut html`.

### Run the live integration tests

Requires the stack to be deployed (see `infrastructure/`) and AWS credentials in the environment.

```bash
# Use defaults (eu-central-1, weather-data-dev, weather-ingest-dev)
pytest tests/test_integration_live.py -v

# Override for a different environment
WEATHER_API_URL=https://<id>.execute-api.<region>.amazonaws.com/readings \
DYNAMODB_TABLE=weather-data-prod \
INGEST_FUNCTION_NAME=weather-ingest-prod \
AWS_DEFAULT_REGION=eu-central-1 \
pytest tests/test_integration_live.py -v
```

The live tests write to reserved device IDs (64000–64007) and delete all written records in teardown. They are safe to run against a live stack.

To skip live tests when running the full suite:

```bash
pytest tests/ -m "not live"
```

### Validate a packet manually

Useful for checking the decoder against a known-good packet from the firmware.

```python
import base64, struct

# Build a test packet (device 1, ts 1700000000, temp 23, hum 65)
from src.ingest import decode_packet, crc16_ccitt

data = struct.pack("<BHIhH", 1, 1, 1700000000, 23, 65)
crc  = crc16_ccitt(data)
pkt  = data + struct.pack("<H", crc)

print(decode_packet(pkt))
# {'version': 1, 'device_id': 1, 'timestamp': 1700000000,
#  'temperature': 23, 'humidity': 65, 'ttl': 1700604800}
```

### Package for deployment

The Terraform `archive_file` data source in `infrastructure/stage1/lambda.tf` and `infrastructure/stage2/lambda.tf` packages each function automatically on `terraform apply`. To package manually:

```bash
zip dist/ingest.zip src/ingest.py
zip dist/query.zip  src/query.py
```
